## Photo Report สำหรับหน้างานบนมือถือ

หน้า `Sidebar.html` เป็นหน้ากรอกงานแบบ Mobile-first สำหรับทีมหน้างาน ไม่จำลองหน้ากระดาษ A4 เพื่อให้ใช้งานบนจอเล็กได้ง่าย โดยบนมือถือจะขยายเต็มความกว้างหน้าจอ ใช้ตัวอักษรและปุ่มขนาดใหญ่ และแบ่งการทำงานเป็นเลือก Job, ตรวจความคืบหน้า, เติมรูปที่ยังขาด และบันทึก/พิมพ์. หน้า A4 ใช้รูปจาก Drive ของ Job ที่เลือก โดยไม่สร้างแท็บรายงานแยก

ระบบยังคงใช้ช่องรูป 9 ช่องตามเอกสารจริง ได้แก่รูปจุดติดตั้ง 1 ช่อง และรูปก่อน/หลังติดตั้ง 4 แถวรวม 8 ช่อง. งานนี้เป็นงานกลางตาม Job จึงไม่ผูกกับผู้ใช้งานคนใดคนหนึ่ง ทุกคนสามารถเลือก Job เดิมแล้วเติมเฉพาะช่องที่ยังขาดได้ หน้ามือถือจะแสดงสถานะข้างเลข Job เช่น `ยังไม่เริ่ม`, `มีแล้ว 3/9` หรือ `ครบ 9/9` พร้อม progress bar และรายการรูปแบบการ์ดที่กดง่าย

หน้างานสามารถกด **เลือกรูปหัวตาราง** เพื่อเลือก 1 รูปสำหรับช่องป้ายหน่วยงาน และกด **เลือกรูปก่อนติดตั้งหลายรูป** หรือ **เลือกรูปหลังติดตั้งหลายรูป** เพื่อเลือกหลายไฟล์พร้อมกัน ระบบจะเรียงรูปลงช่องว่าง 1–2–3–4 ให้อัตโนมัติ ไม่ต้องกดเลือกช่องทีละช่อง. หากต้องการแก้เฉพาะช่องใด ให้กดการ์ดช่องนั้นแล้วเลือกรูปใหม่หรือกด **ลบรูปช่องนี้**. การแตะรูปตัวอย่างจะเปิดดูแบบเต็มจอในมือถือ. การลบจะล้าง URL ของช่องนั้นและย้ายไฟล์รูปของช่องนั้นใน Drive ลงถังขยะ หากมีแท็บรายงานรุ่นเก่าจะลบรูปช่องนั้นออกด้วย แต่ไม่ลบแท็บ

เมื่อกลับมาทำ Job เดิม ระบบจะโหลดรูปเดิม วันที่ติดตั้ง และความคืบหน้ากลับมาให้. การอัปโหลดรูปจะบันทึกต้นฉบับลง Drive และอัปเดตตารางกลางอัตโนมัติ จึงไม่ต้องมีปุ่มบันทึกขนาดใหญ่ค้างอยู่ด้านล่าง. ปุ่มพิมพ์เอกสารขนาดเล็กอยู่ข้างแถบความคืบหน้าและไม่บังพื้นที่ระหว่างเลื่อนดูช่อง. ระบบใช้ Script Lock ขณะเขียนข้อมูล เพื่อป้องกันการอัปโหลดจากหลายคนชนกัน. กด **พิมพ์งานค้าง** ได้เมื่อมีรูปอย่างน้อย 1 ช่อง

กด **ดูใบงาน A4** แล้วรอรูปโหลดครบก่อนกด **สั่งพิมพ์** โดยค่าเริ่มต้นจะเปิด **แนบภาพขยายสำหรับอ่านเลขครุภัณฑ์** ซึ่งเพิ่มภาพต้นฉบับรูปละหน้า A4 ต่อท้ายหน้ารายงานรวม เพื่อไม่บีบตัวเลขให้อยู่ในช่องสูงเพียง 38 มม. หากต้องการเฉพาะหน้ารวมให้เอาเครื่องหมายถูกออก เพื่อพิมพ์หรือ Save as PDF โดยไม่แตะชีตรายงาน หากเปิดรายงานจาก Portal หรือเรียก `createJobPdf(jobNo)` ระบบจะโหลดรูปของ Job นั้นลง `Photo_Report` เดิมแล้วสร้าง PDF ภายใต้ Script Lock ไม่มีการสร้างแท็บ `REPORT_เลขJob` เพิ่ม เอกสารใน `Photo_Report` กลางจะแสดง Job ล่าสุดที่มีการเตรียมรายงาน หากหลายคนใช้งานพร้อมกันควรพิมพ์จากหน้า A4 หรือใช้ไฟล์ PDF ที่สร้างเสร็จแล้ว แทนการเปิดชีตกลางค้างไว้

ต้นฉบับจะเก็บใน Drive โดยไม่บีบอัดซ้ำ เมื่อต้องฝังภาพลง `Photo_Report` ระบบจะใช้ต้นฉบับถ้าเป็น JPG/PNG/GIF และไม่เกิน 2 MB มิฉะนั้นจะขอภาพจาก Drive เริ่มที่ 2000px และลดขนาดตามจำเป็น หน้า A4 โหลดรูปต้นฉบับเต็มทีละรูปผ่านข้อมูล base64 จาก Apps Script โดยไม่ลดเหลือ 2000px และไม่ต้องเปิดไฟล์เป็นสาธารณะ สำหรับเลขครุภัณฑ์ให้ใช้หน้า A4 > สั่งพิมพ์ > Save as PDF เพื่อรักษารายละเอียดต้นฉบับ รูปขนาดเล็กหรือช่องพิมพ์ขนาดเล็กยังมีข้อจำกัดเรื่องรายละเอียด และต้องตรวจ PDF จริงหลัง Deploy

## IT Rental Portal เวอร์ชันใหม่

ไฟล์ `IT_Rental.xlsx` มี 6 ชีต ได้แก่ `Dashboard`, `Asset_Master`, `Delivery_Form`, `Return_Form`, `Movement_Log` และ `Photo_Report` หน้า Photo Report คงดีไซน์เดิมไว้ และใช้ Responsive เฉพาะเมื่อเปิดบนมือถือหรืออุปกรณ์สัมผัส โดยจะแสดงเต็มความกว้างจอและเรียงการ์ดก่อน/หลังเป็นคอลัมน์เดียว ส่วนคอมพิวเตอร์ยังคงโครง Bento เดิม หากหน้าเว็บบนมือถือยังดูเป็น Desktop ให้ปิดเมนู **Desktop site / เว็บไซต์เดสก์ท็อป** ใน Chrome หรือ Safari แล้วเปิด Web App URL ใหม่โดยไม่ใช้การซูมของเบราว์เซอร์

ระบบใหม่เพิ่มหน้า `Portal.html` เพื่อใช้เป็นหน้าเว็บหลัก โดยเปิดผ่าน URL:

```text
WEB_APP_URL?page=portal
```

URL เดิม `?page=asset`, `?page=manage` และ `?page=dashboard` จะเปิด Portal เดียวกันเพื่อรองรับลิงก์เดิม

Portal มีแท็บภาพรวมสำหรับดูจำนวนชุดตามสถานะ, ตาราง `Asset_Master` สำหรับค้นหาและแก้ไขข้อมูลชุดอุปกรณ์ครบตามฟิลด์หลัก A:AD โดยไม่เขียนทับสูตรคอลัมน์ AA และ AB, และแท็บเอกสารสำหรับเปิดชีตจริงเพื่อแก้ไข จัดหน้า และพิมพ์ ได้แก่ `Delivery_Form`, `Return_Form`, `Movement_Log` และ `Photo_Report`

หากต้องการปรับหน้าเอกสารให้ตรงกับไฟล์ Excel ต้นฉบับ ให้แก้ไขใน Google Sheet โดยตรงแล้วใช้คำสั่ง **File > Print** ของแต่ละชีต ระบบเว็บจะเป็นศูนย์กลางสำหรับเลือกเอกสารและเปิดชีต ไม่พยายามสร้างฟอร์มพิมพ์เลียนแบบ Excel ใน HTML

## วิธีติดตั้ง

1. เปิดไฟล์ Google Sheet ที่มี Spreadsheet ID ข้างต้น และตรวจสอบว่ามีชีตชื่อ `Photo_Report` กับ `Asset_Master`.
2. เลือก **Extensions > Apps Script** เพื่อสร้างสคริปต์ที่ผูกกับไฟล์ชีตนั้นโดยตรง การผูกสคริปต์กับชีตมีความสำคัญ เพราะเมนูแบบกำหนดเองจะทำงานกับสคริปต์ที่ผูกกับไฟล์เท่านั้น [1].
3. เปิดไฟล์ `Code.gs` จากโครงการนี้ แล้วคัดลอกเนื้อหาทั้งหมดไปแทนที่ไฟล์ `Code.gs` ใน Apps Script.
4. สร้างไฟล์ HTML ชื่อ `Sidebar`, `Portal` และ `AssetMaster` แล้วคัดลอกเนื้อหาจากไฟล์ `.html` ที่ตรงกันไปวาง. สำหรับเวอร์ชันใหม่ให้มี `Portal.html` ด้วย.
5. กด **Save** จากนั้นเลือกฟังก์ชัน `checkPhotoReportSetup` และ `checkWebAppFiles` แล้วกด **Run** หนึ่งครั้งเพื่ออนุญาตสิทธิ์และตรวจว่าไฟล์ HTML ครบ. `checkWebAppFiles` ควรแสดง `Sidebar`, `Portal` และ `AssetMaster` เป็น `found: true`.
6. กลับไปที่ Google Sheet แล้วรีเฟรชหน้าเว็บ หากเมนูยังไม่ปรากฏ ให้ปิดแล้วเปิดไฟล์ใหม่อีกครั้ง.
7. เลือกเมนู **ระบบจัดการรูปภาพ > เปิดหน้าต่างอัปโหลดรูป** จากนั้นเลือก Job ประเภทรูป และไฟล์รูปภาพ แล้วกด **อัปโหลดเข้าชีท**.

### หากเปิดใช้งานเป็น Web App

โค้ดมีฟังก์ชัน `doGet()` แล้ว สำหรับกรณีที่สร้าง Deployment แบบ Web App ให้เลือก **Deploy > New deployment > Web app** แล้วตั้งค่าให้สคริปต์ทำงานในฐานะบัญชีที่มีสิทธิ์เข้าถึง Spreadsheet และโฟลเดอร์รูป จากนั้นกด **Deploy** และเปิด URL ของ Web App หากแก้ไขโค้ดภายหลัง ให้สร้างเวอร์ชันใหม่หรือเลือก **Edit deployment** แล้วเปลี่ยนเป็นเวอร์ชันล่าสุดก่อนเปิด URL อีกครั้ง

ข้อผิดพลาด `Script function not found: doGet` หมายถึง Deployment ถูกเปิดผ่าน URL ของ Web App แต่ในเวอร์ชันที่ Deploy อยู่ไม่มีฟังก์ชัน `doGet()` การเพิ่มฟังก์ชันนี้ใน `Code.gs` และ Deploy เวอร์ชันใหม่จะแก้ปัญหาดังกล่าว

### วิธีใช้งานบนมือถือ

ให้เปิด URL ของ Web App ผ่าน Chrome หรือ Safari บนมือถือ ไม่ใช่เปิดจากแอป Google Sheets โดยตรง หน้า Photo Report ใช้ **ดีไซน์เดิม** แต่มี Responsive สำหรับมือถือขนาดประมาณ 390–430 CSS px โดยการ์ด **ก่อนติดตั้ง** และ **หลังติดตั้ง** จะเรียงเป็นบล็อกเต็มความกว้าง พร้อมช่องย่อย 1–4 ช่อง และมีช่องเล็กสำหรับ **รูปหัวตาราง / จุดติดตั้ง** ส่วนคอมพิวเตอร์จะยังคง Bento สองคอลัมน์ตามดีไซน์เดิม ระบบตรวจ User-Agent และอุปกรณ์สัมผัสด้วย เพื่อให้มือถือที่ Chrome เปิด Desktop site อยู่ยังถูกจัดเป็น Mobile layout ได้

หลังเลือก Job แล้ว ระบบจะจำ Job ล่าสุดไว้ในเบราว์เซอร์เพื่อไม่ต้องเลือกซ้ำทุกครั้ง ให้แตะการ์ด **ก่อนติดตั้ง** หรือ **หลังติดตั้ง** แล้วเลือกหลายรูปจากคลังพร้อมกัน หรือเลือกถ่ายรูปด้วยกล้องทีละรูป ระบบจะเรียงรูปลงช่องว่างให้อัตโนมัติและบันทึกลง Drive/ตารางกลางทันที ไม่ต้องกดปุ่มบันทึกงาน หากต้องการเปลี่ยนรูป ให้แตะหมายเลขช่องในหน้าต่างรูปแล้วเลือกภาพใหม่ได้ ภาพตัวอย่างใน Bento สามารถแตะเพื่อดูเต็มจอได้

หน้าเว็บจะแสดงจำนวนรูปที่เก็บแล้ว เช่น `5/9` เพื่อให้คนหน้างานรู้ว่าขาดอีกกี่รูป งานเดียวกันสามารถให้หลายคนเลือก Job เดิมแล้วช่วยเติมรูปต่อได้ การลบหรือเปลี่ยนรูปจะอัปเดตช่องในรายงานทันที ส่วนปุ่ม **พิมพ์เอกสาร** เป็นปุ่มเล็กข้างสถานะความคืบหน้า และใช้สร้าง PDF ของ Job ที่เลือก โดยไฟล์ PDF จะถูกเก็บไว้ในโฟลเดอร์ Drive เดียวกับรูปงานนั้น

ครั้งแรกที่กด **ถ่ายรูปด้วยกล้อง** เบราว์เซอร์อาจขอสิทธิ์ใช้กล้อง ให้กดอนุญาต หากใช้งานเป็นประจำ แนะนำให้เลือกคำสั่ง **Add to Home Screen / เพิ่มไปยังหน้าจอหลัก** ของเบราว์เซอร์ เพื่อเปิดหน้า Photo Report ได้เร็วขึ้นเหมือนแอป

### การจัดการ Asset_Master

หน้า Photo Report จะไม่มีหน้าจัดการข้อมูลรวมอยู่แล้ว โดยให้เปิดหน้าเว็บจัดการแยกผ่าน URL ของ Web App โดยเติม `?page=asset` ต่อท้าย URL เช่น `https://script.google.com/macros/s/DEPLOYMENT_ID/exec?page=asset` หน้านี้ใช้ดูรายการ Job ค้นหาด้วยเลข Job อาคาร ชั้น แผนก หรือห้อง กด **+ เพิ่ม Job** หรือ **แก้ไข** เพื่อใช้งาน Popup ได้ ระบบจะเขียนเฉพาะคอลัมน์ A และ D:G ตามโครงสร้างเดิม และไม่แตะคอลัมน์อื่นของชีต

ในหน้า Photo Report และหน้า Asset_Master จะมีปุ่ม **เปิด Asset_Master** และ **เปิด Photo_Report** สำหรับเปิด Google Sheet จริงในหน้าใหม่ การแก้ไขเซลล์ การจัดหน้า และการสั่งพิมพ์ต้องทำใน Google Sheet โดยตรง ไม่สามารถแก้ไขเซลล์ภายในหน้า Web App ได้

หน้า IT Rental Portal เพิ่มป้าย **สถานะเตรียมเครื่อง** ในตาราง Asset_Master โดยไม่เพิ่มเมนูใหม่ สถานะจะถูกเก็บในคอลัมน์ AE และเลือกเปลี่ยนจากตารางได้ทันที ได้แก่ `รับเข้าแล้ว`, `ลง Windows`, `ลงโปรแกรม`, `รอ Activate`, `พร้อมติดตั้ง` และ `ติดปัญหา` สำหรับข้อมูลเดิมที่ยังไม่มีค่าใน AE ระบบจะแสดงเป็น `ลง Windows` เพื่อให้ตรงกับสภาพปัจจุบันของเครื่องที่รับเข้ามาแล้ว โดยไม่เขียนค่าทับลงชีตอัตโนมัติ

ข้อมูลรับคืนจะแสดงแยกในคอลัมน์ **รับคืน / COM S/N เดิม** โดยอ่านจากช่อง `COM S/N เดิม` ที่มีอยู่แล้ว หากมีค่า ระบบจะแสดง `รับคืนแล้ว` พร้อมหมายเลข COM S/N เดิม และถ้าไม่มีค่าจะแสดง `ยังไม่คืน` ระบบจะแสดงจำนวนเครื่องที่มี COM S/N เดิมบนหน้า Dashboard ให้ดูได้ทันที

เพิ่มคอลัมน์ **เลข IP** ต่อท้ายข้อมูลเดิมในคอลัมน์ `AF` ของ `Asset_Master` โดยไม่แทรกคอลัมน์กลางตาราง จึงไม่กระทบสูตร `AA:AB` หรือสถานะเตรียมเครื่อง `AE` สามารถกรอกหรือแก้ไขได้จาก Popup ของ Portal และค้นหาจากช่องค้นหา Asset_Master ได้

เลข Job ต้องขึ้นต้นด้วย `JOB-` และระบบจะป้องกันเลข Job ซ้ำ เมื่อบันทึกข้อมูลใหม่แล้ว ให้กลับไปที่หน้า Photo Report ผ่านลิงก์ด้านบนของหน้าเว็บจัดการ หรือเปิด URL เดิมโดยไม่ใส่ `?page=asset`

หากกดปุ่มเปิดชีตแล้วขึ้นว่าไม่มีสิทธิ์ ให้ตรวจสอบว่าเบราว์เซอร์ลงชื่อเข้าใช้ด้วยบัญชี Google เดียวกับเจ้าของหรือผู้แก้ไข Spreadsheet ID ที่ตั้งไว้ และผู้ใช้นั้นมีสิทธิ์ **Editor** ในไฟล์ Google Sheet หาก Web App เปิดไม่ได้ ให้ Deploy เวอร์ชันล่าสุดและเปิดด้วยบัญชีเดียวกับบัญชีที่เป็นผู้ Deploy ตามค่า `access: MYSELF` ใน manifest

### การพิมพ์เป็น A4

หน้า Web App จัดวางให้มีสัดส่วนคล้ายแบบฟอร์ม A4 แนวตั้งสำหรับใช้งานและตรวจสอบบนมือถือ ส่วนการพิมพ์รายงานจาก Google Sheet ให้เปิดชีต `Photo_Report` แล้วเลือก **File > Print** ตั้งค่า **Paper size: A4**, **Orientation: Portrait**, **Scale: Fit to page** และเลือกพิมพ์เฉพาะชีตปัจจุบัน หากเทมเพลตของคุณเป็นแนวนอน ให้เปลี่ยน Orientation เป็น **Landscape** ก่อนพิมพ์

## โครงสร้างข้อมูลที่คาดหวังใน `Asset_Master`

สคริปต์ใช้ข้อมูลตั้งแต่แถวที่ 4 โดยอ่านค่า `Job No.` จากคอลัมน์ A และนำค่าคอลัมน์ D ถึง G มาต่อเป็นสถานที่ ดังนั้นโครงสร้างหลักควรเป็นดังนี้

| คอลัมน์ | ข้อมูล |
| --- | --- |
| A | Job No. เช่น `JOB-001` |
| D | อาคาร |
| E | ชั้น |
| F | แผนก |
| G | ห้อง |

หากข้อมูลเริ่มที่แถวอื่นหรืออยู่คนละคอลัมน์ ให้แก้ฟังก์ชัน `getJobData()` ใน `Code.gs`

| --- | --- | --- | --- |
| **แทรกเป็น Over-grid image ตามสคริปต์นี้** | รูปถูกเก็บในชีตโดยตรง ไม่ต้องแชร์ไฟล์เป็นสาธารณะ และสคริปต์สามารถลบรูปเก่าที่เกาะเซลล์เดียวกันก่อนวางรูปใหม่ได้ รูปจะเป็นวัตถุเหนือเซลล์ ไม่ใช่ค่าภายในเซลล์ | ไม่มีค่าใช้จ่ายเพิ่มเติมนอกเหนือจาก Google Drive/Sheets ที่ใช้อยู่ | ปานกลาง |

สำหรับเทมเพลต Photo Report ที่ต้องการควบคุมตำแหน่งรูปและไม่ต้องเปิดไฟล์เป็นสาธารณะ สคริปต์นี้เลือกวิธีแรก โดยใช้ `insertImage(blob, column, row)` และตั้ง anchor cell กับขนาดภาพตามพื้นที่ของเซลล์ [2]. การอ่านโฟลเดอร์ด้วย ID และสร้างไฟล์ด้วย Blob ใช้บริการ DriveApp ของ Apps Script [3].

## ข้อควรทราบ

สคริปต์จะเก็บรูปใหม่ใน Drive และอัปเดต URL ของช่องนั้นใน `Photo_File_Index` ก่อนย้ายรูปเดิมของช่องเดียวกันลงถังขยะ แท็บรายงานรุ่นเก่าจะไม่ถูกลบอัตโนมัติและยังใช้ตรวจความคืบหน้าได้ หากไม่มีไฟล์ต้นฉบับเก่าใน Drive ระบบจะขอให้อัปโหลดรูปช่องนั้นใหม่ก่อนพิมพ์

ผู้ใช้ที่กดใช้งานต้องมีสิทธิ์แก้ไข Spreadsheet และมีสิทธิ์เขียนในโฟลเดอร์ Drive หากพบข้อผิดพลาดว่าไม่พบโฟลเดอร์หรือไม่มีสิทธิ์ ให้ตรวจสอบว่าบัญชี Google ที่ใช้เปิดชีตสามารถเปิด Folder ID ที่ระบุได้

## ตำแหน่งรูปตอนอัปโหลดและตอนพิมพ์

หน้าอัปโหลดคงช่องเดิม 1–4 ของก่อน/หลังติดตั้งไว้เสมอ รูปที่อัปโหลดช่อง 3 จะยังอยู่ช่อง 3 เมื่อกลับมาเปิดงาน ส่วนหน้ารายงาน A4 จะนำเฉพาะรูปที่มีมาเรียงชิดกันจากบนลงล่างเป็น 1, 2, 3, 4 แยกฝั่งก่อนและหลัง เช่น ช่องก่อนติดตั้ง 1 และ 3 จะแสดงเป็นรูปก่อนติดตั้ง 1 และ 2 ในรายงาน ไม่มีกรอบรูปว่างคั่นกลางหรือแถวรูปว่างท้ายรายงาน โดยคงช่องป้ายหน่วยงานด้านบนไว้รออัปโหลด ภาพขยายต่อท้ายใช้เลขลำดับเดียวกับหน้ารวม การสร้าง PDF ผ่าน `Photo_Report` ก็จัดภาพชิดด้านบนด้วยหลักเดียวกัน แต่คงโครงเซลล์เทมเพลตเดิมไว้ การจัดพิมพ์ไม่เปลี่ยน URL หรือช่องต้นทางใน `Photo_File_Index`

## อัปเดตเวอร์ชันที่ไม่สร้างแท็บราย Job

อัปเดต `Code.gs` และ `Sidebar.html` ใน Apps Script แล้ว Deploy Web App เวอร์ชันใหม่ ระบบจะเพิ่มคอลัมน์สถานที่และวันที่ท้าย `Photo_File_Index` เดิมโดยรักษา URL รูปเก่าไว้ ไม่ต้องลบแท็บ `REPORT_JOB-…` เพื่อเริ่มใช้เวอร์ชันนี้ และไม่ควรลบแท็บเก่าจนกว่าจะตรวจว่ารูปและงานเก่ากลับมาเปิด/พิมพ์ได้ครบแล้ว

ทดสอบในเครื่องพัฒนาด้วย `node --test tests/*.test.cjs` จากโฟลเดอร์โครงการ ชุดทดสอบใช้ตัวจำลอง Google APIs เพื่อตรวจว่าอัปโหลด/บันทึก/ลบ/เปิดรายงาน/สร้าง PDF ไม่สร้างแท็บราย Job พร้อมตรวจการโหลดรูปก่อนพิมพ์ ผลนี้ไม่ได้ยืนยันการแปลง PDF หรือความคมชัดบน Google จริง หลัง Deploy ให้ทดสอบอัปโหลดรูปโทรศัพท์เกิน 2 MB กับ Job ทดสอบ รีเฟรชหน้าเพื่อโหลดรูปกลับ เปิดหน้า A4 และ Save as PDF รวมถึงตรวจว่าจำนวนแท็บไม่เพิ่มตาม Job

## รายงานความคืบหน้าสำหรับผู้บริหาร

ในแท็บ **ภาพรวม** มีส่วน **รายงานเครื่องที่ติดตั้งเสร็จ** แสดงเครื่องทั้งหมด ติดตั้งเสร็จ คงเหลือ และร้อยละความคืบหน้า พร้อมสรุปตามตึก/ชั้น/แผนกและรายการเครื่องที่เสร็จแล้ว (Job, สถานที่, รุ่น, S/N, IP และความครบถ้วนของงาน) กด **พิมพ์ / บันทึก PDF ความคืบหน้า** เพื่อออกรายงาน A4 แนวนอน โดยไม่สร้างแท็บหรือไฟล์ในชีตเพิ่ม

เกณฑ์เสร็จคือสถานะการติดตั้ง `ติดตั้งเสร็จ` ตามข้อมูลที่โหลดจาก Asset_Master ไม่ใช้สถานะเตรียมเครื่องแทน ส่วน `งานจบครบ` แสดงแยกตามเกณฑ์หน้าติดตามงานเดิมซึ่งต้องส่งมอบ อุปกรณ์เสริม และรูปหลักครบ ตัวเลขเป็นภาพข้อมูลเมื่อโหลดหน้าล่าสุด ไม่ใช่จำนวนที่เสร็จในวันนั้นหรือประวัติย้อนหลัง ให้รีเฟรชก่อนเสนอรายงานและดูเวลาที่ดึงข้อมูลซึ่งแสดงตามเขตเวลา Asia/Bangkok อัปเดต `Portal.html` ใน Apps Script และ Deploy เวอร์ชันใหม่เพื่อเปิดใช้งาน

## อัปโหลดต้นฉบับโดยมีคิวงานค้าง

หน้าเก็บรูปส่งต้นฉบับทีละรูป โดยไม่บีบอัด และนับว่าบันทึกสำเร็จเฉพาะเมื่อ Apps Script ยืนยันการเขียน Drive/ตารางกลางแล้ว แถบสถานะติดด้านบนแสดงจำนวนยืนยันแล้ว รอส่ง และส่งไม่สำเร็จอย่างชัดเจน มีปุ่มลองส่งใหม่และเตือนเมื่อจะออกจากหน้าที่ยังมีงานค้าง เบราว์เซอร์ที่รองรับจะขอป้องกันหน้าจอดับขณะส่ง

ก่อนส่งจะเก็บต้นฉบับและรหัสคำขอใน IndexedDB ของเครื่องนั้น เมื่อกลับมาเปิดหน้าเดิมในเบราว์เซอร์/เครื่องเดิมจะส่งรูปค้างต่อโดยใช้รหัสเดิม เซิร์ฟเวอร์ตรวจรหัสในชื่อไฟล์เพื่อใช้ไฟล์เดิมเมื่อได้รับคำขอซ้ำ หลังเซิร์ฟเวอร์ยืนยันแล้วจึงล้างสำเนาในคิว หากพื้นที่เต็มหรือใช้ที่เก็บข้อมูลไม่ได้ หน้าจอจะแจ้งชัดว่าต้องเปิดหน้านี้ไว้จนเสร็จ การล็อกจอ/ปิดเบราว์เซอร์อาจหยุดการส่ง การเก็บคิวช่วยส่งต่อเมื่อเปิดใหม่ ไม่ได้รับรองการส่งต่อขณะปิดจอ และไม่สามารถกู้คิวได้หลังล้างข้อมูลเว็บหรือเปลี่ยนเครื่อง

## ปรับเฉพาะภาพป้ายครุภัณฑ์ในพรีวิว Portal

ใน **ติดตามงาน → ดูพรีวิว A4** ระบบโหลดรูปต้นฉบับผ่านสคริปต์และรอโหลดครบก่อนเปิดปุ่มพิมพ์ การเรียงภาพก่อน/หลังชิดด้านบนใช้ทั้งสองฝั่ง โดยไม่ย้ายช่องอัปโหลด ส่วนช่องป้ายหน่วยงานและหน้าตาฟอร์มยังคงไว้

กด **ปรับป้ายครุภัณฑ์** บนภาพที่ต้องการ แล้วใช้ตัวเลื่อนขยาย ซ้าย/ขวา และขึ้น/ลงให้บริเวณป้ายอยู่ในกรอบ กด **ใช้ภาพนี้ในรายงาน** จะปรับเฉพาะภาพนั้นในการพิมพ์จากพรีวิวนี้ ไม่แก้ภาพต้นฉบับใน Drive ไม่แก้ตัวเลข ไม่กระทบภาพช่องอื่น และไม่เปลี่ยนการ Export ผ่านชีตโดยตรง สามารถคืนมุมเดิมหรือยกเลิกได้ การจัดมุมเก็บไว้ในหน้า Portal ที่เปิดอยู่ เมื่อรีโหลดหน้าให้จัดใหม่หากต้องการ

## รายงานเลขครุภัณฑ์เครื่องเดิมที่รับคืน

หน้าภาพรวมมีรายงานรับคืนพร้อมปุ่มพิมพ์/PDF อ้างอิง `oldComSn` (COM S/N เดิม) และ `oldUpsSn` (UPS S/N เดิม) แยกจาก S/N เครื่องใหม่ ยอดคอมและ UPS รวมเลขจริงที่ไม่ซ้ำกับเครื่องที่มีแต่ไม่มีเลข แยกประเภท สรุปตามตึก/ชั้น/แผนก และเลขซ้ำพร้อม Job ที่เกี่ยวข้องเพื่อให้ตรวจสอบ ช่องว่างหมายถึงไม่มีเครื่องกลับ ส่วนค่า `ไม่มี` หรือ `ไม่มีเลข` หมายถึงมีเครื่องกลับแต่ไม่มีเลขครุภัณฑ์ โดยนับเป็นเครื่องรับคืนแยกตามแถวและไม่ถือข้อความเหล่านี้เป็นเลขซ้ำ หากเลขซ้ำข้ามพื้นที่ ผลรวมรายพื้นที่อาจสูงกว่ายอดไม่ซ้ำทั้งระบบ

ชุดนี้ต้องอัปเดต `Code.gs`, `Sidebar.html` และ `Portal.html` ใน Apps Script แล้ว Deploy เวอร์ชันใหม่ ไม่เพิ่มแท็บราย Job ชุดทดสอบใช้ Google API จำลอง ส่วนการเก็บ/กู้คิว IndexedDB และการปรับภาพก่อน/หลังได้ตรวจเพิ่มเติมด้วย Chromium และ PDF จากข้อมูลทดสอบ ต้องตรวจอีกครั้งบน Web App จริงและอุปกรณ์หน้างานหลัง Deploy

ยอดรับคืนรวมของคอม/UPS = จำนวนเลขจริงที่ไม่ซ้ำ + จำนวนรายการมีเครื่องแต่ไม่มีเลข รายงานแสดงแยกเครื่องมีเลขและเครื่องไม่มีเลข โดยช่องที่ไม่กรอกแสดงว่าง ทั้งบนหน้าภาพรวมและ PDF

## รับคืน PC / จอ / UPS แยกประเภท

คืนช่อง `oldMonitorSn` จากโค้ดรุ่นก่อน โดยใช้คอลัมน์ AJ (36) หัวคอลัมน์ `เลขครุภัณฑ์จอมอนิเตอร์` เดิม ไม่แทรกคอลัมน์กลาง ไม่เขียนทับคอลัมน์ AI ของ Hub หรือ AK ของตัวเลือกเดิม และไม่ล้างค่าจอเมื่อ client รุ่นเก่าไม่ได้ส่งฟิลด์นี้มา ถ้า AJ เป็นคอลัมน์อื่นระบบจะหยุดพร้อมแจ้งให้ตรวจหัวคอลัมน์ แทนการเขียนทับข้อมูล

ใน Popup แก้ไขข้อมูลและหน้ารายละเอียดมีเลขครุภัณฑ์จอแยกจาก PC/UPS หน้าภาพรวมและ PDF รับคืนสรุปยอดทั้งสามประเภท รวมกรณีมีเฉพาะจอกลับ ไม่มี PC หรือ UPS ทุกประเภทใช้หลักเดียวกัน: ช่องว่าง = ไม่มีของกลับ; `ไม่มี` หรือ `ไม่มีเลข` = มีของกลับแต่ไม่มีเลข; เลขจริง = มีของกลับพร้อมเลขครุภัณฑ์ เลขซ้ำตรวจแยกประเภท ยอดคอม จอ และ UPS นับแยกกัน ไม่จำเป็นต้องเท่ากันหรือมี UPS ทุกเครื่อง ไม่มีตัวชี้วัดหรือคอลัมน์คืนครบชุด ช่องที่ไม่กรอก รวมถึงประเภทเครื่องเมื่อไม่มีคอมและจอกลับ แสดงว่างทั้งหน้าภาพรวมและ PDF

อัปเดต `Code.gs` และ `Portal.html` แล้ว Deploy ใหม่เพื่อเปิดใช้ช่องจอและรายงานสามประเภท ข้อมูลจอเดิมใน AJ จะถูกอ่านกลับโดยไม่ต้องกรอกใหม่

## ประเภทเครื่องเดิม PC / AIO ในรายงานรับคืน

ถ้าช่องคอมเดิมและจอเดิมมีข้อมูลใน Job เดียวกัน จะจัดประเภทเครื่องเดิมเป็น PC ไม่ใช่ AIO โดยรวมค่าบ่งชี้ `ไม่มี` / `ไม่มีเลข` ซึ่งหมายถึงมีจอแต่ไม่มีเลขครุภัณฑ์ด้วย ถ้ามีจอแต่ช่องคอมเดิมว่าง จะแสดง `รับคืนเฉพาะจอ — กรุณาตรวจสอบ` และไม่เพิ่มยอดคอมรับคืน ช่อง `ประเภทเครื่องเดิม` แสดงทั้งบนหน้าภาพรวมและ PDF ไม่ใช้ประเภทชุดเครื่องเช่าใหม่มาตัดสินเครื่องเดิม

ตามเกณฑ์ที่ผู้ใช้งานยืนยัน กรณีมีคอมกลับแต่ช่องจอว่างให้จัดเป็น `AIO` รวมคอมที่กรอก `ไม่มี` หรือ `ไม่มีเลข` ด้วย หากช่องคอมและจอว่างทั้งคู่จะไม่จัดเป็น AIO แม้มี UPS กลับ การจัดประเภทไม่เขียนเปลี่ยนข้อมูลต้นฉบับ การแก้ส่วนนี้อัปเดตเฉพาะ `Portal.html` แล้ว Deploy ใหม่

## เปลี่ยนใบงานก่อนหน้า / ถัดไปในพรีวิว A4

แถบด้านบนของ **ติดตามงาน → ดูพรีวิว A4** มีปุ่ม **ใบงานก่อนหน้า / ใบงานถัดไป** และลำดับ `ใบงาน X / Y` ใช้ไล่ Job ตามลำดับรายการที่ผ่านการค้นหา/ตัวกรองในตารางตอนเปิดพรีวิว โดยไม่ต้องกลับไปเลือกจากตาราง ปุ่มปิดที่ใบงานแรก/สุดท้ายและไม่วนกลับ เปลี่ยนใบงานระหว่างรอรูปได้ โดยผลโหลดของ Job เก่าจะไม่เขียนทับ Job ใหม่ ปุ่มพิมพ์จะรอรูปของ Job ปัจจุบันโหลดครบก่อน ค่าซูมที่กดใช้แล้วจะเก็บแยกแต่ละ Job/ช่องในหน้า Portal ที่เปิดอยู่ เมื่อย้อนกลับมาจะยังได้ค่าเดิม อัปเดต `Portal.html` และ Deploy ใหม่เพื่อใช้งาน

## สรุปติดตั้งและรับคืนตามหน่วยงานสำหรับผู้บริหาร

หน้าภาพรวมมีสรุปรวมด้านบน ใช้ชื่อ `department` ที่ตัดช่องว่างหัวท้ายเป็นกลุ่ม หน่วยงานชื่อเดียวกันรวมยอดแม้อยู่คนละตึกหรือชั้น ช่องชื่อว่างรวมใน `ไม่ระบุหน่วยงาน` ตัวกรองหน่วยงานใช้กับการ์ด กราฟ รายงานติดตั้ง รายงานรับคืน รายงานปัญหา และปุ่มพิมพ์ในหน้าภาพรวมทั้งหมด โดยไม่กรองข้อมูลต้นฉบับหรือหน้าติดตามงาน เมื่อรีเฟรชข้อมูลยังคงตัวกรองไว้ถ้าชื่อนั้นยังมีอยู่

สรุปแสดงทั้งหมด / ติดตั้งเสร็จ / คงเหลือ / เปอร์เซ็นต์ / ติดตั้งเสร็จแต่รอตรวจงาน / งานติดปัญหา พร้อมรับคืน AIO / PC / จอ / UPS และจำนวนคอม จอ UPS ที่ไม่มีเลขครุภัณฑ์ รายการรอตรวจงานอ้างอิงเกณฑ์ `workStatus` เดิม (ส่งมอบ อุปกรณ์เสริม รูปหลัก) หรือยังไม่มีข้อมูลติดตามงาน ไม่ถือช่องรับคืนว่างเป็นงานค้าง ปุ่ม `ดูงาน` เปิดหน้าติดตามงานและค้นหา Job นั้นเพื่อไล่ตรวจต่อ

ยอดรับคืนในสรุปผู้บริหารนับตามรายการ Job ไม่หักเลขซ้ำออก: มีคอมและจอในแถวเดียวกัน = PC; มีคอมและช่องจอว่าง = AIO; UPS นับแยก เมื่อติดตั้งเสร็จแต่ช่องคอม จอ และ UPS ว่างทั้งสาม แสดงว่า `ยังไม่มีข้อมูลรับคืน` ไม่ใช้ยืนยันว่าเป็นงานติดตั้งเพิ่ม จออย่างเดียวไม่เพิ่มยอดคอม และจะแสดงหมายเหตุพร้อม Job ให้ตรวจเฉพาะเมื่อพบกรณีนี้ ไม่เพิ่มจำนวนงานติดปัญหาหรือรอตรวจความครบถ้วน ยอดจอจึงเท่ากับ PC + รายการรับคืนเฉพาะจอ และผลรวมรายหน่วยงานเท่ากับยอดรวมตาม Job

เลขซ้ำแยกเป็นตาราง “เลขครุภัณฑ์ซ้ำที่ต้องตรวจสอบ” ระบุประเภท เลข Job และหน่วยงานทุกจุดที่เกี่ยวข้อง ทั้งหน้าจอและ PDF โดยไม่แก้เลขอัตโนมัติ ทะเบียนเลขครุภัณฑ์รับคืนเดิมยังแสดงยอดเลขจริงไม่ซ้ำรวมรายการไม่มีเลข พร้อมคำอธิบายให้แยกจากยอดตาม Job ในสรุปผู้บริหาร

ปุ่ม `พิมพ์สรุปผู้บริหาร` สร้างรายงาน A4 แนวนอนตามหน่วยงานที่เลือก พร้อมตารางรวมและรายการต้องติดตาม ใช้ข้อมูลชุดเดียวกับหน้าจอและเวลาโหลดข้อมูล Asia/Bangkok ไม่สรุปยอดรายวันย้อนหลังจากข้อมูลที่ไม่มีวันที่ ไม่สร้างแท็บหรือแก้ข้อมูลในชีต อัปเดตเฉพาะ `Portal.html` ใน Apps Script แล้ว Deploy เวอร์ชันใหม่เพื่อใช้งาน

## รายงานภาพคอมติดตั้งเสร็จรายหน่วยงาน

ในหน้าภาพรวม เลือกหน่วยงานแล้วกด **รายงานภาพคอมรายหน่วยงาน** ข้างปุ่มพิมพ์สรุปผู้บริหาร ใช้เฉพาะแถวที่ผลติดตั้งเป็น `ติดตั้งเสร็จ` และดึงเฉพาะรูป `after1` (หลังติดตั้ง 1) ซึ่งเป็นรูปเครื่องคอมหนึ่งภาพต่อ Job ไม่ดึงภาพก่อนติดตั้ง ป้ายครุภัณฑ์ หรือ UPS มาแทน หากไม่มี after1 จะแสดงช่องแจ้งภาพที่ยังขาด พร้อมเลข Job ในสถานะโหลด

จัดกลุ่มชื่อหน่วยงานเดียวกันแม้คนละชั้น เรียง Job และจัดพิมพ์ A4 แนวตั้งหน้าละ 4 เครื่อง (2 × 2) หน่วยงานใหม่ขึ้นหน้าใหม่ พร้อมชื่อหน่วยงาน จำนวนเครื่อง เลข Job จุดติดตั้ง และเวลาโหลดข้อมูล หน้าจอมือถือแสดงภาพเรียงลงด้านล่าง ส่วน PDF ยังคง 2 × 2 เลือก `ทุกหน่วยงาน` เพื่อรวมหลายหน่วยงานเป็นรายงานเดียวได้

โหลดต้นฉบับจาก Drive ผ่าน Apps Script เดิม ไม่ต้องเปิดแชร์รูปสาธารณะ จำกัดคำขอพร้อมกันไม่เกินสองงาน แสดงความคืบหน้า และเปิดปุ่มพิมพ์เมื่อภาพทั้งหมดที่พบโหลดและแสดงได้แล้ว หากโหลดผิดพลาดให้กดโหลดใหม่ ไม่มีการพิมพ์รูปที่โหลดค้างเป็นรายงานสำเร็จ การปิดพรีวิวจะหยุดเริ่มคำขอใหม่และละทิ้งผลที่กลับมาช้า ภาพที่ไม่มีอยู่จะแจ้งแยกจากข้อผิดพลาดการโหลด

รายงานใช้ภาพคอมเต็มภาพ แยกจากการซูม/เลื่อนในใบงานรายเครื่อง ไม่แก้รูปต้นฉบับ ไม่เปลี่ยนใบงานเดิม และไม่สร้างแท็บราย Job อัปเดตเฉพาะ `Portal.html` ใน Apps Script แล้ว Deploy เวอร์ชันใหม่เพื่อใช้งาน ชุดทดสอบและ PDF ที่ตรวจในเครื่องใช้ข้อมูลและ Google API จำลอง ต้องตรวจข้อมูลจริงหลัง Deploy

## ชุดเอกสารส่งผู้บริหารแบบกระชับ

เลือกหน่วยงานแล้วกด **ชุดเอกสารส่งผู้บริหาร** เพื่อเตรียม PDF ไฟล์เดียว เริ่มด้วยสรุป A4 แนวนอน: งานทั้งหมด / ติดตั้งเสร็จ / คงเหลือ / เปอร์เซ็นต์ ตามด้วยยอดรับคืน AIO PC จอ UPS ติดตั้งเพิ่ม ยอดไม่มีเลข และจำนวนเรื่องที่ต้องติดตาม พร้อมตารางตามหน่วยงาน จากนั้นแนบภาพคอม `after1` ของงานติดตั้งเสร็จ A4 แนวตั้ง หน้าละ 4 เครื่อง ใช้ข้อมูลหน่วยงานและเวลาชุดเดียวกันทั้งสรุปและภาพ หากยังไม่มีงานติดตั้งเสร็จจะพิมพ์ได้เฉพาะสรุป

ค่าเริ่มต้นเน้นเอกสารส่งผู้บริหาร ไม่แนบตารางราย Job และเลขซ้ำทั้งหมด หากต้องใช้ตรวจสอบ ให้เลือก **แนบรายละเอียด Job และเลขซ้ำในรายงานพิมพ์** ก่อนกดสร้างชุด รายละเอียดจะแยกเป็นภาคผนวกก่อนภาพ สามารถใช้ปุ่ม **พิมพ์เฉพาะสรุป** หรือ **รายงานภาพคอมรายหน่วยงาน** เพื่อออกเอกสารแต่ละส่วนแยกได้ หน้าภาพรวมแสดงการ์ดหลักเพียง 4 ตัวและย่อรายละเอียดตรวจสอบไว้ให้กดเปิด

อัปเดต `Portal.html` และ Deploy ใหม่ก่อนใช้งาน ตรวจ PDF แบบรวมทั้งหน้าสรุปแนวนอนและภาพแนวตั้งด้วย Chromium จากข้อมูลจำลองแล้ว จำนวนหน้าสรุปขึ้นอยู่กับจำนวนหน่วยงาน ไม่ตัดรายการเพื่อบังคับให้เหลือหน้าเดียว


## ยอดติดตั้งในเอกสารใช้รายงานความคืบหน้าเดิมเป็นแหล่งคำนวณ

สรุปผู้บริหารและชุดเอกสารเรียก `buildCompletionReportData` เดียวกับรายงานเครื่องที่ติดตั้งเสร็จ ทั้งยอดรวม ติดตั้งเสร็จ คงเหลือ เปอร์เซ็นต์ และงานจบครบ โดยใช้ข้อมูลและตัวกรองหน่วยงานชุดเดียวกัน จำนวนรอตรวจความครบถ้วน = ติดตั้งเสร็จ − งานจบครบ ไม่ใช้จำนวนงานจบครบแทนยอดติดตั้งเสร็จ

รายการ `ยังไม่มีข้อมูลรับคืน` ใช้เฉพาะงานติดตั้งเสร็จที่ช่องรับคืนทั้งสามว่าง ไม่รวมงานที่ยังไม่เริ่มหรือยังไม่เสร็จ และไม่เรียกรายการเหล่านี้ว่างานติดตั้งเพิ่ม แต่ยอดอุปกรณ์รับคืนยังนับตามข้อมูลที่กรอกจริงในแต่ละ Job ชุดทดสอบจำลอง 156 รายการ / เสร็จ 126 / คงเหลือ 30 / 81% / งานจบครบ 80 เพื่อเทียบกับเกณฑ์อ้างอิง ไม่ตรึงตัวเลขเหล่านี้ในระบบจริง อัปเดต `Portal.html` และ Deploy ใหม่ รายงานจากข้อมูลจริงต้องเทียบเวลาโหลดและหน่วยงานที่เลือกตรงกัน


## ข้อความในแอปและเอกสาร

ใช้คำทั่วไปและข้อความสั้น เช่น เลขงาน ทะเบียนอุปกรณ์ ตัวอย่างใบงาน รอตรวจข้อมูล และยังไม่มีข้อมูลรับคืน ตัดคำอธิบายการทำงานภายในออกจากรายงานและหน้าพิมพ์ ใช้ชื่อสถานะและข้อความแจ้งผลให้ตรงกันทั้งหน้าเว็บ ใบงาน รายงานผู้บริหาร ใบส่งมอบ และใบรับคืน ชื่อชีต ฟิลด์ และค่าสถานะที่บันทึกเดิมยังใช้เหมือนเดิม

รายงานไม่ใช้ช่องรับคืนว่างเป็นหลักฐานว่าติดตั้งเพิ่ม หัวข้อเดิมแสดงเป็น `ยังไม่มีข้อมูลรับคืน` สำหรับงานติดตั้งเสร็จที่ยังว่างทั้งสามช่อง หน้าอัปโหลดบอกชัดว่ากำลังเตรียมส่ง กำลังส่ง บันทึกแล้ว หรือไม่มีอินเทอร์เน็ต โดยไม่บอกว่าบันทึกสำเร็จก่อนส่งเสร็จ

ตรวจพบและแก้ตัวแปรการกดค้างช่องรูปที่ยังไม่ได้กำหนดค่า เพื่อให้แตะช่องเพิ่มรูปได้ตามปกติ อัปเดต `Code.gs`, `Portal.html`, `Sidebar.html`, `AssetMaster.html` และ `PrintForm.html` แล้ว Deploy เวอร์ชันใหม่เพื่อใช้ข้อความชุดนี้


## ตรวจยอดจากข้อมูลรับคืนและช่องไม่มีเครื่องเดิม

ข้อความที่มีคำว่า `ไม่มีเลข` เช่น `HP ไม่มีเลข`, `DELL ไม่มีเลข` และ `ไม่มีเลขครุภัณฑ์` นับว่ามีอุปกรณ์รับคืนแต่ไม่มีเลข ไม่รวมข้อความเหล่านี้ในการตรวจเลขครุภัณฑ์ซ้ำ เครื่องยี่ห้อเดียวกันที่ไม่มีเลขยังนับแยกแต่ละรายการ

อ่านช่องเดิม AK (37) เมื่อหัวคอลัมน์เป็น `ไม่มีเครื่องเดิมให้นำกลับ` โดยไม่เขียนหรือเพิ่มคอลัมน์ สรุปแยกงานติดตั้งเสร็จที่เลือกช่องนี้และไม่มีรายการรับคืนเป็น `ไม่มีเครื่องเดิมให้นำกลับ` ส่วนงานติดตั้งเสร็จที่ช่องรับคืนว่างแต่ไม่ได้เลือกช่องนี้เป็น `ยังไม่มีข้อมูลรับคืน` หากชีตรุ่นเก่าไม่มีหัวคอลัมน์นี้ จะไม่เดาว่ามีการยืนยันแล้ว ทั้งสองจำนวนแสดงแยกในหน้าสรุปและ PDF ไม่ใช้ช่องนี้ลบล้างข้อมูลรับคืนที่กรอกไว้

อัปเดต `Code.gs` และ `Portal.html` แล้ว Deploy ใหม่ ชุดทดสอบไม่เก็บข้อมูลจริงหรือรหัสซอฟต์แวร์จาก CSV ไว้ใน repository
