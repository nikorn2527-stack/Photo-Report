# Photo Report – Google Apps Script

โครงการนี้เป็น Google Apps Script สำหรับอัปโหลดรูปภาพจาก Sidebar แล้วบันทึกไฟล์ลงในโฟลเดอร์ Google Drive ที่กำหนด พร้อมแทรกรูปลงในเทมเพลตชีต `Photo_Report` โดยตรง รูปที่แทรกเป็นภาพแบบ **วางทับบนตาราง (Over-grid image)** จึงไม่ต้องเปิดไฟล์รูปเป็นสาธารณะเพื่อให้สูตร `IMAGE()` โหลดรูป โดย Google Sheets จำกัด Blob ที่ใช้แทรกภาพไว้ไม่เกิน 2 MB ต่อรูป [2].

## วิธีติดตั้ง

1. เปิดไฟล์ Google Sheet ที่มี Spreadsheet ID ข้างต้น และตรวจสอบว่ามีชีตชื่อ `Photo_Report` กับ `Asset_Master`.
2. เลือก **Extensions > Apps Script** เพื่อสร้างสคริปต์ที่ผูกกับไฟล์ชีตนั้นโดยตรง การผูกสคริปต์กับชีตมีความสำคัญ เพราะเมนูแบบกำหนดเองจะทำงานกับสคริปต์ที่ผูกกับไฟล์เท่านั้น [1].
3. เปิดไฟล์ `Code.gs` จากโครงการนี้ แล้วคัดลอกเนื้อหาทั้งหมดไปแทนที่ไฟล์ `Code.gs` ใน Apps Script.
4. สร้างไฟล์ HTML ใหม่ชื่อ `Sidebar` แล้วคัดลอกเนื้อหาจาก `Sidebar.html` ไปวาง.
5. กด **Save** จากนั้นเลือกฟังก์ชัน `checkPhotoReportSetup` แล้วกด **Run** หนึ่งครั้งเพื่ออนุญาตสิทธิ์การเข้าถึงชีตและโฟลเดอร์ Drive. ฟังก์ชันนี้ไม่แก้ไขข้อมูล จะคืนชื่อไฟล์ชีต ชื่อโฟลเดอร์ และสถานะการพบชีต.
6. กลับไปที่ Google Sheet แล้วรีเฟรชหน้าเว็บ หากเมนูยังไม่ปรากฏ ให้ปิดแล้วเปิดไฟล์ใหม่อีกครั้ง.
7. เลือกเมนู **ระบบจัดการรูปภาพ > เปิดหน้าต่างอัปโหลดรูป** จากนั้นเลือก Job ประเภทรูป และไฟล์รูปภาพ แล้วกด **อัปโหลดเข้าชีท**.

### หากเปิดใช้งานเป็น Web App

โค้ดมีฟังก์ชัน `doGet()` แล้ว สำหรับกรณีที่สร้าง Deployment แบบ Web App ให้เลือก **Deploy > New deployment > Web app** แล้วตั้งค่าให้สคริปต์ทำงานในฐานะบัญชีที่มีสิทธิ์เข้าถึง Spreadsheet และโฟลเดอร์รูป จากนั้นกด **Deploy** และเปิด URL ของ Web App หากแก้ไขโค้ดภายหลัง ให้สร้างเวอร์ชันใหม่หรือเลือก **Edit deployment** แล้วเปลี่ยนเป็นเวอร์ชันล่าสุดก่อนเปิด URL อีกครั้ง

ข้อผิดพลาด `Script function not found: doGet` หมายถึง Deployment ถูกเปิดผ่าน URL ของ Web App แต่ในเวอร์ชันที่ Deploy อยู่ไม่มีฟังก์ชัน `doGet()` การเพิ่มฟังก์ชันนี้ใน `Code.gs` และ Deploy เวอร์ชันใหม่จะแก้ปัญหาดังกล่าว

### วิธีใช้งานบนมือถือ

ให้เปิด URL ของ Web App ผ่าน Chrome หรือ Safari บนมือถือ ไม่ใช่เปิดจากแอป Google Sheets โดยตรง หน้าจอจะแสดงเป็นแบบฟอร์มคล้ายเทมเพลต Photo Report โดยมีช่องรูปตามตำแหน่ง **ป้ายชื่อหน่วยงาน / จุดติดตั้ง**, **ก่อนติดตั้ง 1–4** และ **หลังติดตั้ง 1–4**

หลังเลือก Job แล้ว ระบบจะจำ Job ล่าสุดไว้ในเบราว์เซอร์เพื่อไม่ต้องเลือกซ้ำทุกครั้ง ให้แตะช่องรูปที่ต้องการ ระบบจะแสดงเมนูแบบ **Bottom Sheet ด้านล่างหน้าจอ** ให้เลือก **เลือกรูปจากคลัง** หรือ **ถ่ายรูปด้วยกล้อง** เมื่อเลือกรูปแล้ว ระบบจะแสดงตัวอย่างรูปก่อนส่ง ให้ตรวจสอบรูปและกด **บันทึกรูปช่องนี้** รูปจะถูกบันทึกลงโฟลเดอร์ Drive และแทรกลงช่องที่ตรงกันในชีทรายงานของ Job ทันที หากต้องการเปลี่ยนรูป ให้แตะช่องเดิมแล้วบันทึกรูปใหม่ได้

ปุ่ม **บันทึกงาน** และ **สั่งพิมพ์งาน** จะติดอยู่ด้านล่างหน้าจอเพื่อกดได้ตลอดแม้เลื่อนดูช่องรูปอยู่ เมื่อทำงานไปบางส่วน ให้กด **บันทึกงาน** ระบบจะสร้างหรืออัปเดตชีทรายงานแยกชื่อ `REPORT_เลขJob` ทำให้ Job ที่ยังไม่เสร็จไม่ถูกทับด้วย Job อื่น เมื่อต้องการทำต่อ ให้เลือก Job เดิมจากรายการ ช่องที่มีรูปแล้วจะแสดงสถานะ **มีรูปแล้ว** จากนั้นแตะช่องที่ยังว่างเพื่อใส่รูปต่อได้

ปุ่ม **สั่งพิมพ์งาน** จะสร้างไฟล์ PDF A4 ของ Job ที่เลือก แล้วเปิดลิงก์ PDF สำหรับพิมพ์ โดยไฟล์ PDF จะถูกเก็บไว้ในโฟลเดอร์ Drive เดียวกับรูปงานนั้น

ครั้งแรกที่กด **ถ่ายรูปด้วยกล้อง** เบราว์เซอร์อาจขอสิทธิ์ใช้กล้อง ให้กดอนุญาต หากใช้งานเป็นประจำ แนะนำให้เลือกคำสั่ง **Add to Home Screen / เพิ่มไปยังหน้าจอหลัก** ของเบราว์เซอร์ เพื่อเปิดหน้า Photo Report ได้เร็วขึ้นเหมือนแอป

### การจัดการ Asset_Master

หน้า Photo Report จะไม่มีหน้าจัดการข้อมูลรวมอยู่แล้ว โดยให้เปิดหน้าเว็บจัดการแยกผ่าน URL ของ Web App โดยเติม `?page=asset` ต่อท้าย URL เช่น `https://script.google.com/macros/s/DEPLOYMENT_ID/exec?page=asset` หน้านี้ใช้ดูรายการ Job ค้นหาด้วยเลข Job อาคาร ชั้น แผนก หรือห้อง กด **+ เพิ่ม Job** เพื่อเพิ่มข้อมูลใหม่ หรือกด **แก้ไข** ที่รายการเดิมเพื่อแก้ไขข้อมูล ระบบจะเขียนเฉพาะคอลัมน์ A และ D:G ตามโครงสร้างเดิม และไม่แตะคอลัมน์อื่นของชีต

เลข Job ต้องขึ้นต้นด้วย `JOB-` และระบบจะป้องกันเลข Job ซ้ำ เมื่อบันทึกข้อมูลใหม่แล้ว ให้กลับไปที่หน้า Photo Report ผ่านลิงก์ด้านบนของหน้าเว็บจัดการ หรือเปิด URL เดิมโดยไม่ใส่ `?page=asset`

### การพิมพ์เป็น A4

หน้า Web App จัดวางให้มีสัดส่วนคล้ายแบบฟอร์ม A4 แนวตั้งสำหรับใช้งานและตรวจสอบบนมือถือ ส่วนการพิมพ์รายงานจาก Google Sheet ให้เปิดชีต `Photo_Report` แล้วเลือก **File > Print** ตั้งค่า **Paper size: A4**, **Orientation: Portrait**, **Scale: Fit to page** และเลือกพิมพ์เฉพาะชีตปัจจุบัน หากเทมเพลตของคุณเป็นแนวนอน ให้เปลี่ยน Orientation เป็น **Landscape** ก่อนพิมพ์

## โครงสร้างข้อมูลที่คาดหวังใน `Asset_Master`

สคริปต์ใช้ข้อมูลตั้งแต่แถวที่ 4 โดยอ่านค่า `Job No.` จากคอลัมน์ A และนำค่าคอลัมน์ D ถึง G มาต่อเป็นสถานที่ ดังนั้นโครงสร้างหลักควรเป็นดังนี้

| คอลัมน์ | ข้อมูล |
| --- | --- |
| A | Job No. เช่น `JOB-001` |
| D | อาคาร |
| E | ชั้น |
| F | แผนก |
| G | ห้อง |

หากข้อมูลเริ่มที่แถวอื่นหรืออยู่คนละคอลัมน์ ให้แก้ฟังก์ชัน `getJobData()` ใน `Code.gs`

| --- | --- | --- | --- |
| **แทรกเป็น Over-grid image ตามสคริปต์นี้** | รูปถูกเก็บในชีตโดยตรง ไม่ต้องแชร์ไฟล์เป็นสาธารณะ และสคริปต์สามารถลบรูปเก่าที่เกาะเซลล์เดียวกันก่อนวางรูปใหม่ได้ รูปจะเป็นวัตถุเหนือเซลล์ ไม่ใช่ค่าภายในเซลล์ | ไม่มีค่าใช้จ่ายเพิ่มเติมนอกเหนือจาก Google Drive/Sheets ที่ใช้อยู่ | ปานกลาง |
| ใช้สูตร `=IMAGE(URL)` | รูปอยู่ในเซลล์และปรับตามเซลล์ได้ง่าย แต่ URL ต้องเข้าถึงได้จาก Sheets และมักต้องจัดการสิทธิ์การแชร์ไฟล์หรือ URL เพิ่มเติม | ไม่มีค่าใช้จ่ายเพิ่มเติม แต่มีความเสี่ยงด้านการเปิดเผยไฟล์ | ต่ำ |

สำหรับเทมเพลต Photo Report ที่ต้องการควบคุมตำแหน่งรูปและไม่ต้องเปิดไฟล์เป็นสาธารณะ สคริปต์นี้เลือกวิธีแรก โดยใช้ `insertImage(blob, column, row)` และตั้ง anchor cell กับขนาดภาพตามพื้นที่ของเซลล์ [2]. การอ่านโฟลเดอร์ด้วย ID และสร้างไฟล์ด้วย Blob ใช้บริการ DriveApp ของ Apps Script [3].

## ข้อควรทราบ

สคริปต์จะบันทึกรูปใหม่ลงในโฟลเดอร์ที่กำหนดทุกครั้งที่อัปโหลด และจะแทนที่เฉพาะรูปที่วางทับอยู่ที่ anchor cell เดียวกันในชีตเท่านั้น ไฟล์รูปเดิมใน Drive จะไม่ถูกลบ เพื่อป้องกันการสูญหายของข้อมูลและเพื่อให้มีประวัติไฟล์เก็บไว้ตรวจสอบภายหลัง

ผู้ใช้ที่กดใช้งานต้องมีสิทธิ์แก้ไข Spreadsheet และมีสิทธิ์เขียนในโฟลเดอร์ Drive หากพบข้อผิดพลาดว่าไม่พบโฟลเดอร์หรือไม่มีสิทธิ์ ให้ตรวจสอบว่าบัญชี Google ที่ใช้เปิดชีตสามารถเปิด Folder ID ที่ระบุได้
